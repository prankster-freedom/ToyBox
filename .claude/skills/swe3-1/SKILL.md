# swe3-1（detailed-design / 工程 3-1: 詳細設計）

詳細設計を行う。

対象: $ARGUMENTS

## 手順

1. **既存の設計書の確認**: 対象の機能に関連する詳細設計書が既にあるかを確認する。既存の機能に関係する場合は、既存のドキュメントを更新する。新規に作成する場合は [template.md](template.md) のひな形を使う。
2. **詳細設計**: 詳細設計書を作成・更新する。
   - ドキュメントはファイル単位ではなく、**機能単位（Feature-based）** で作成する
   - 格納先は doc スキルの「ソフトウェアプロジェクトのドキュメント」（`<プロジェクト>/doc/3.detailed_design/features/<feature名>.md`）
   - 設計の各項目には、対応する要求仕様・アーキテクチャ設計の ID を記載する
3. **【承認】設計レビュー**: 詳細設計の結果をユーザーとレビューし、承認を得る。
4. **反映**: レビューの結果を反映する。
   - 設計判断の背景・根拠（なぜその設計にしたか、前提とした制約、採らなかった案とその理由など）は、後の設計変更でのデグレを防ぐため、該当する設計項目の近くに記載する
   - 議論の経緯（いつ・誰が・どのようなやり取りで決めたか）は設計書に書かず、コミットメッセージの本文に残す（`AGENTS.md` 1.9）
5. **【承認】最終版の確認**: 最終版のドキュメントをユーザーに報告し、明示的に承認を得たら完了とする。
