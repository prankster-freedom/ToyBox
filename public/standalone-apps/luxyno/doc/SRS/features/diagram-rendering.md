# Feature Requirement Specification: diagram-rendering

本ドキュメントは、Luxyno における Mermaid ダイアグラムの描画スタイル（高速モードおよび Visualモード 4 スタイル）、ビューモード、図の個別操作・エクスポート、全図種描画、および自動 2 段組みレイアウトの機能要求仕様を定義する。

対応する全体 SRS: [doc/SRS.md](../../SRS.md)

## 対象機能要求一覧

| ID     | 機能名                     | 概要                                                             |
| :----- | :------------------------- | :--------------------------------------------------------------- |
| FR-001 | ビューモード切替           | `Split`（エディタ＋プレビュー）、`Canvas`（プレビューのみ）、`Code`（エディタのみ）の 3 モードを切り替える |
| FR-002 | 高速モード（仕様書表示）   | Markdown と Mermaid 図をフラットで高密度なエンジニアリング仕様書スタイルで描画する |
| FR-003 | Visualモード               | 文書と Mermaid 図を 4 種のインフォグラフィックスタイルで描画する |
| FR-005 | 図の個別操作・エクスポート | 各ダイアグラムカードの拡大表示、表示倍率切替（Fit / 1:1）、SVG・PNG ダウンロード、HTML エクスポートを行う |
| FR-008 | 同梱サンプルの全図種の描画 | 同梱の `sample.md` に記載したすべての図を、高速モードと Visualモードの 4 スタイルの両方で意図どおりに描画する |
| FR-015 | Visualモードの自動 2 段組みレイアウト | Visualモードのスラブにおいて、本文と 1 つの Mermaid 図があり図が収まる場合は、左に本文・右に図の 2 段組みで表示する |

## 機能要求の詳細

### FR-001: ビューモード切替

- `Split`（エディタ＋プレビュー）、`Canvas`（プレビューのみ）、`Code`（エディタのみ）の 3 種類の表示モードをヘッダーのトグルボタンで即座に切り替えられること。
- モード切替時もエディタの入力内容やスクロール状態、キャッシュを維持すること。

### FR-002: 高速モード（仕様書表示）におけるダイアグラムデザイン

- エンジニアリング仕様書向けのクリーンで高密度なスタイルを維持する。
- **ノード（箱）の造形**: 単一カラーのクリーンな 1.75px 枠線とフラット塗り。
- **エッジ（結線）**: 2px の落ち着いたソリッドライン。
- 起動から描画、スクロールまでの絶対的な軽快性を最優先する。

### FR-003: Visualモード（インフォグラフィック 4 スタイル）

- **モード切替 UI**: 画面上部のヘッダーに、Split / Canvas / Code と並ぶセグメントボタングループ（`.pill-container`）として「高速モード」と「Visualモード」を配置し、現在どちらのモードであるかを明示するとともに、ワンクリックで直接選択できるようにする。クイック・スタイルバー（パステル図形 / 2段カード等）を選択した際も、「Visualモード」が自動的にアクティブになる。
- **インフォグラフィックスタイル**: Visualモード起動時に、以下の 4 つの本格的なグラフィックデザインスタイルを即座に適用・切替可能とする。

#### 1. Pastel Shapes（パステルグラデーション図形フロー）
- **背景**: ティール〜シャンパン〜ピンクの優美なパステルグラデーション ＋ 半透明ホワイト方眼グリッド。
- **箱の造形**: 枠線（`stroke`）を完全撤廃。面（サーフェス）としてのソフトドロップシャドウ（`feDropShadow`）を適用。
  - 開始 / 終了ノード: 丸角ピルカプセル（純白、またはライムグリーン〜ミントのグラデーション）。
  - 処理ノード: サンセットアンバー〜ゴールドのグラデーション矩形。
  - 判断・分岐ノード（ひし形）: アクアスカイ〜シアンのグラデーション。
  - 入出力ノード（平行四辺形）: コーラルピンク〜ピーチのグラデーション。
- **結線**: チャコールグレー（`#334155`）のエディトリアル矢印。

#### 2. 2-Tier Cards（2 段組インフォグラフィックカード）
- **ヘッダープレート**: `FLOW CHART // INFOGRAPHIC` タイトルプレート ＋ 4 色バー（Coral, Gold, Periwinkle, Teal）。
- **箱の造形**: 縦長インフォグラフィックカード。上段にステップ記号（A, B, C...）付きのカラーキャップ、下段に立体ソフトシャドウを持つホワイトボディの 2 層構造。

#### 3. Vibrant Circles & Dots（サークル＆ドットコネクタ）
- **箱の造形**: 豊かな 5 色ベタ塗りサークル（テラコッタレッド、スチールブルー、キャメルオーカー、セージグリーン、ディープバイオレット）＋ 白抜き文字。
- **結線**: 丸ドット破線（`stroke-linecap: round; stroke-dasharray: 0 10; stroke-width: 4px`）。

#### 4. Editorial Cream（マガジンチャート風）
- **背景**: ウォームクリーム（`#F7F4EB`）。
- **箱の造形**: 純白の真円・ピルカプセル ＋ ダスティローズ（`#D68C8C`）のバッジ ＋ セージグリーンの太いフラット矢印。

### FR-005: 図の個別操作・エクスポート

- 各ダイアグラムカードのヘッダーから以下の個別操作を行えること：
  - **拡大表示（Expand）**: モーダルで図を大画面表示。
  - **表示倍率切替（Fit / 1:1）**: カード幅に自動調整する Fit 表示と、原寸大（1:1）表示のトグル。
  - **SVG ダウンロード**: 現在描画されているスタイルを保ったままベクター画像として保存。
  - **高解像度 PNG ダウンロード**: ラスタライズした PNG 画像として保存。
  - **HTML エクスポート**: スタンドアロンで閲覧可能な自己完結型 HTML ファイルを出力。

### FR-008: 同梱サンプルの全図種の描画

- `sample.md` に記載された Markdown 記法および Mermaid（`10.9.1`）で描ける主要図種（flowchart, sequenceDiagram, classDiagram, stateDiagram, erDiagram, gitGraph, gantt, pie, journey, mindmap 等）をすべて意図どおりに描画すること。
- 「意図どおり」の基準：
  - 構文エラーにならず、Mermaid が生成した図の構造（要素の形・配置・接続）が崩れない。
  - 文字・線・矢じり・塗りが背景と見分けられ、判読できる（NFR-004）。
  - Visualモードの各スタイルの装飾は、その図種で意味の通る要素にのみ適用し、構造を破壊しない。
  - サンプルには通常の図に加え、ノードの多い大きなフローチャートや複合状態を持つ状態遷移図を含め、大きな図の判読性（NFR-005）を確認できること。

### FR-015: Visualモードの自動 2 段組みレイアウト

- Visualモードのスラブ（`h2` ごとのセクション）が次の条件をすべて満たすときは、見出し（`h2`）の下を左右の 2 段組みにし、左カラムに本文（段落・リスト・引用・表・コードブロック等）、右カラムに Mermaid 図カードを並べて表示する：
  1. スラブ内に本文要素が 1 個以上あり、かつ Mermaid 図スロットがちょうど 1 個であること
  2. 画面幅が 2 段組みに十分であること（デスクトップ幅 768px 以上。767px 以下では縦積みの 1 段組みにフォールバック）
  3. `Fit` 表示において、図の最小幅（NFR-005 の文字サイズ 10px 下限による幅）が右カラムの表示枠に収まり、横スクロールが発生しないこと（`vp.scrollWidth <= vp.clientWidth + 1`）
- 本文のみのスラブ、図のみのスラブ、図が 2 つ以上あるスラブ、または図が右カラムからはみ出すスラブ（大きな図や横長の図）、および `1:1` 原寸表示に切り替えた場合は、自動的に 1 段組み（全幅表示）へフォールバックする（`.is-stacked`）。
- **背景・根拠**: DTP（誌面・展示パネル設計）の版面割り付けでは、解説文と図版を左右に並べることで横長の大画面での空間効率と視線誘導が向上する。一方で大きな図を一律に 2 段組みに押し込むと横スクロールが発生して展示品質を損ねるため、図のサイズと可読性下限に応じて 2 段組みと 1 段組みを自動判定する。Markdown に段組み用の独自拡張記法は導入しない。
