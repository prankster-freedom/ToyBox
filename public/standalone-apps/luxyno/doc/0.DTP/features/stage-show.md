# Visualモードの舞台演出（stage-show）

ブランドの中心にある「構文に、光と舞台を。」（[1.2.2](../../1.SRS.md#122-コアフィロソフィーphilosophy)）のうち、「光」をシグナル・ライト、「舞台」をステージ発表として形にする。

対応する要求: `FR-018`, `FR-019`（[1.SRS/features/stage-show.md](../../1.SRS/features/stage-show.md)）／ラフ: `RGH-010`〜`012`, `RGH-105`, `RGH-904`〜`906`（[roughs/README.md](../roughs/README.md)）

## 光の表現の見直しの根拠

以前の演出（`RGH-009`）を実際の画面で確かめると、次の理由で「光」として読めなかった。

| 課題 | 実際の見え方 | 原因 |
| :--- | :----------- | :--- |
| 光に見えない | 暗い線の上に、14px の色付きの破線が重なっているだけに見える | 明るさの芯も、周囲へのにじみも、尾もない。均一な不透明度の線は「光」ではなく「線」として読まれる |
| 流れに意味がない | 全部の線で同時に、同じ破線が繰り返し動く | 破線の周期を線の長さと関係なく固定し、開始の遅れも番号順で決めていた。図の構造（どこから、どこへ）を伝えていない |
| 届いても何も起きない | 光が線の端で消える | 光と到達先のノードの間に因果がない |
| 手順の線が光らない | 線の色が変わるだけに見える | 2px の線の中のグラデーションを動かしているだけで、線の外へのにじみがない |
| Light で見えない | 白や淡い色の光が背景に溶ける | 光を明るさで表現しようとしている。明るい背景の上では、足せる明るさが残っていない |

Web の表現手法を調べ（[参考](#参考)）、次の知見を採った。

- 光らしさは、白に近い芯（ホットコア）の周りに、色の付いた光輪を段階的に弱めて重ねることで作る
- 線に沿った光は `stroke-dashoffset` か、線上の位置に要素を動かす方法で作るのが定番。ただし均一な線になりやすく、尾を細くするには別の工夫が必要
- 動く光のにじみは、毎フレーム `filter` でぼかすより、あらかじめぼかした放射グラデーションを重ねるほうが軽いという報告がある（検索結果の要約で確かめた。Luxyno で 2 つの方式を比べて計測はしていない）
- 光輪は明るい背景の上では溶けて見えなくなる。暗い背景が光の本来の舞台である

**採った方針**: 光を「線の飾り」ではなく「図の意味を運ぶ信号」にする。図の根から下流へ順に伝わり、届いたノードが反応する。Dark と舞台（ステージ発表）では加算で本物の光にし、Light では彩度の高い光輪で白い芯を浮かせる。

## シグナル・ライト

### DTP-LIGHT-010 光の構造

1 つの光は、頭・芯・光輪・尾の 4 要素からなる彗星とする。

| 要素 | 表現 | 値（図の座標系） |
| :--- | :--- | :--------------- |
| 頭   | 白の小さな粒と、色の付いた大きなにじみ | 半径 22（Light）/ 28（Dark）、白の粒はその 36% |
| 芯   | 白。頭で太く、尾へ向かって細く、薄くなる。柔らかい粒を線に沿って密に並べて描く | 半径は頭で約 5、尾で 1.5 |
| 光輪 | 色の付いたにじみ。頭で広く、尾で狭い | 半径 20（Light）/ 24（Dark）|
| 尾   | 頭の後ろに伸びる長さ。終点に着いたらノードへ吸い込まれるように弱まる | 長さ 132 |

進む速さは図の座標で毎秒 230 とし、線の長さによらず一定にする。長い線ほど時間がかかることが、距離として伝わる。

- 背景（芯を線分ではなく粒で描く）: 線分をつなぐと継ぎ目がはしご状に見え、丸い端にすると数珠のように見えた（`RGH-906`）。

### DTP-LIGHT-020 Light と Dark の光

| 外観 | 合成 | 考え方 |
| :--- | :--- | :----- |
| Dark | 加算（Canvas は `lighter`、ページとは `screen`） | 暗い背景に光を足す。光が重なるほど白に近づく、本物の光のふるまい |
| Light | 通常の重ね合わせ | 足せる明るさがないため、彩度の高い光輪を濃いめに置き、その中の白い芯で光らせる。線が暗い色のときは、線そのものが内側から光って見える |

光の色はスタイルごとに 4 色持ち、図の根からの深さの順に使う（同じ段の光は同じ色）。誌面の `--vs-c1`〜`4` は淡く、光の色にすると溶けるため、同じ色相で彩度を上げた専用の色とする。

| スタイル    | Light の 4 色                           | Dark の 4 色                            |
| :---------- | :-------------------------------------- | :-------------------------------------- |
| `shapes`    | `#F2643D` `#F59E0B` `#0EA5B7` `#43A047` | `#FF9A76` `#FFC857` `#4FD8E8` `#7EE081` |
| `cards`     | `#EA6A47` `#E5A100` `#4F6BED` `#149C9C` | `#FF9D80` `#FFD166` `#8EA6FF` `#5FE0D2` |
| `circles`   | `#E0483D` `#2F88C9` `#F09A27` `#5E8F3A` | `#FF8A7A` `#7CC4F5` `#FFC070` `#A6D96A` |
| `editorial` | `#C95F5F` `#6F9450` `#B8862F` `#5F83A8` | `#F0A6A6` `#B5D69A` `#E6C37A` `#A9C4E4` |

手順の光（`DTP-LIGHT-050`）の色 `--vs-glow` は、`shapes` が 3 色目、それ以外が 1 色目とする（`shapes` は図の基調のアクアに合わせる）。

### DTP-LIGHT-030 背面と前面の 2 層

光は図の背面と前面の 2 枚の層に分けて描く。

| 層   | 描くもの | 効果 |
| :--- | :------- | :--- |
| 背面 | 光輪、ノードの発光 | ノードが光を遮るため、ノードの輪郭が逆光で浮かぶ。文字の上に光が乗らず、読みやすさを損なわない |
| 前面 | 芯、頭 | 線の上で光る |

ノードの発光は、光が届いた瞬間に、ノードの外周へ広がりながら 0.8 秒で消える。

- 背景: ノードの前面に発光を描くと、Light では文字の裏に濁った色のにじみが出た。背面に置くことで、読みやすさと質感の両方が良くなった（`RGH-905`）。

### DTP-LIGHT-040 信号の伝わり方

| 図の種類 | 伝わり方 |
| :------- | :------- |
| フローチャート・状態遷移図 | 入る線のないノード（根）が点灯し、そこから出る線を光が進む。ノードに最初の光が届いた時刻に、そのノードから出る線の光が出発する。分岐は同時に分かれ、合流は最初に届いた光を引き継ぐ |
| シーケンス図 | メッセージを時系列の順に 1 本ずつ流す。会話が再生されるように見せる |

- 閉路（戻りの線）にも光は流すが、すでに点灯したノードからは再び伝わらない。根がない図は、残った線の先頭を起点にする。
- 一巡の最後に 2.2 秒の余韻を置いてから繰り返す。余韻の間は何も描かない。
- 大きな図でも、光が走る時間は 13 秒以内に収める（超える場合は全体を同じ割合で速くする）。

### DTP-LIGHT-050 手順の光

手順型（`DTP-VTPL-040`）の接続線の上を、図と同じ構造の彗星（色は `--vs-glow`）が進む。

- 丸から次の丸まで 1 秒で進み、周期の 70% を走り、残りは余韻とする。
- 丸の下をくぐって進む（丸が光を遮る）。
- 光が丸に届いた瞬間に、丸の周りの輪が光って広がる。シェブロン（`AST-008`）は光の通過に合わせて点灯する。

### DTP-LIGHT-060 光の節度

読解を妨げない（`RGH-903`）ため、次を守る。

- 光は線の上と、届いたノードの周りだけに出す。背景全体を動かさない。
- 画面の外の図は止める。画面に入ったら、図の根から始める。
- 余韻の間は再描画もしない。
- `prefers-reduced-motion: reduce` では、光を一切出さない。

## ステージ発表

### DTP-SHOW-010 舞台

発表は暗転から始める。背景は `#070B14` で、上方からの柔らかいスポットライトを放射グラデーションで置く（静止。`RGH-903`）。アプリの操作部品はすべて隠れる。`T` キーで明るい舞台（`#E9ECF2`）に切り替えられる。

### DTP-SHOW-020 シーンの構図

- 1 シーンの中身は 1 章（`h2`）とする。ヒーローは表紙のシーンとする。
- スラブの枠・背景・影を外し、舞台に直接置く。カードの中ではなく舞台の上に立たせる。
- 版面は最大 `76rem`。`rem` の基準を画面の幅に比例させ（`1.32vw`、15〜36px）、誌面全体を拡大する。大画面でも画面に対する文字の比率が変わらない。
- 中身は上下の中央に置く。画面より長いときは上から置き、スクロールで見せる。

| 要素                 | 大きさ   |
| :------------------- | :------- |
| 表紙の題名           | `3.4rem` |
| 章の見出し           | `1.9rem` |
| ステートメント       | `2.3rem` |
| リード               | `1.7rem` |

### DTP-SHOW-030 図

図のカードの操作部品（`Fit` / `1:1` / `PNG` など）を隠し、図を舞台の残りの高さに収める。小さな図は最大 2.4 倍まで拡大する。文字の下限（`NFR-005`）より小さくなる場合は下限を保ち、残りをスクロールで見せる。

### DTP-SHOW-040 転換

シーンが替わるときは、光の帯が画面を左から右へ 1 秒で横切り、見出しから順に 0.09 秒ずつ遅れて下から現れる。

### DTP-SHOW-050 1 項目ずつ見せる

要点カード・手順は、話す順に 1 項目ずつ見せる。

- 要点カードは、未表示のカードをほぼ見えない濃さ（`0.1`）で沈める。話している項目はスポットライト（`DTP-VTPL-090`）で強調する。
- 手順は、番号の丸を不透明のまま暗くし、文字を沈める。丸を透かすと、光が透けて濁るため。

### DTP-SHOW-060 進行の表示と操作

- 画面の下端に、進行を示す 3px の光の線を置く。左下に章の題、右下に `03 / 15` の形の位置を置く。
- 操作ボタンはマウスを動かしたときだけ出し、2.6 秒で消える。マウスのカーソルも消す。
- 下端は舞台の色へ溶かし、長い図の上でも章の題が読めるようにする。
- 発表の開始時に、操作の案内を 6 秒だけ出す。
