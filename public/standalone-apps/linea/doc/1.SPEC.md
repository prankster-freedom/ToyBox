# 要求仕様書 (1.SPEC.md)

## 1. 概要

**Linea — Visual Markdown & Diagram Studio** は、Markdown 文書と Mermaid ダイアグラムをリアルタイムに編集・プレビュー・エクスポートできるスタンドアロンの Web アプリケーションである。
エンジニアリング仕様書向けのクリーンな通常表示モードと、インフォグラフィック調の 4 スタイルを切り替えられる「Visual Stage」モードを備える。

初期プロトタイプの機能・デザイン仕様は [linea_functional_and_design_specification.md](linea_functional_and_design_specification.md) を参照する。

### FR-006 Markdown ファイルの読み込み

- エディタの内容を、最後に読み込んだ時点から編集していた場合（起動直後の空の状態から入力した場合を含む）は、置き換える前に確認ダイアログを表示し、取り消せるようにする。本アプリには保存機能がなく、置き換えると編集内容が失われるため。
- ブラウザのファイル選択で読み込むため、`index.html` を `file://` で直接開いた場合でも使える。

### FR-007 起動時の初期表示

- サンプル文書は `app.js` に埋め込まない。サンプルは同梱の `sample.md` として提供し、利用者が FR-006 で開く。
- 背景: 埋め込みの文書はソースコードの中にあり、内容の確認・更新がしにくい。起動時に `sample.md` を自動で読み込む案は、`file://` で開いた場合にブラウザの制約で読み込めず、開き方によって動作が変わるため採らない。

### FR-008 同梱サンプルの全図種の描画

- `sample.md` には、Markdown の主な記法と、Mermaid（`10.9.1`）で描ける主な図種の簡単な例を記載する。
- 「意図どおり」とは、次をすべて満たすことをいう。
  - 構文エラーにならず、Mermaid が生成した図の構造（要素の形・配置・接続）が崩れない
  - 文字・線・矢じり・塗りが背景と見分けられ、判読できる（`NFR-004`）
  - Visual Stage の各スタイルの装飾（グラデーション、カード化、円形化など）は、その図種で意味の通る要素にだけ適用する。適用できない図種は、構造を保ったまま、そのスタイルの配色・背景に合わせる
- 背景: Visual Stage の装飾は flowchart・状態遷移図・シーケンス図を前提に作られており、他の図種の要素にそのまま適用すると図が崩れるため。
- `sample.md` には、図種ごとの簡単な例に加え、ノードの多いフローチャート（サブグラフを含む）と、状態の多い状態遷移図（複合状態・分岐・並行を含む）を記載し、大きな図の判読性（`NFR-005`）を確認できるようにする。

### FR-009 同梱サンプルの Markdown 記法の描画

- 「記法ごとに見分けられる」とは、Light / Dark のどちらでも、次をすべて満たすことをいう。
  - 見出しは階層ごとに文字の大きさまたは太さが異なり、本文と見分けられる
  - 箇条書きには記号、番号付きリストには番号が付き、入れ子は字下げされる
  - リンクは本文と異なる色で、リンクと分かる
  - インラインコードとコードブロックは、本文と異なる背景と等幅フォントで表示される
  - 引用は、本文と見分けられる左線と字下げで表示される
  - 表の列は、Markdown で指定した寄せ（左・中央・右）で表示される
  - 水平線は、背景と見分けられる線で表示される
  - HTML で書いた標準の要素（`details` / `summary`、`kbd`、`mark`、`sub` / `sup` など）は、その要素と分かる表示になる
- `sample.md` の HTML の例には、アプリ独自の class を使わず、標準の HTML 要素だけを使う。アプリ独自の装飾（`callout-box`）を使うと、標準の HTML の表示例と区別できないため。
- 背景: 本アプリが読み込む Tailwind CSS は、ブラウザ標準の要素のスタイル（見出しの大きさ、リストの記号、リンクの色など）を初期化する。アプリ側で定義していない要素は本文と同じ表示になり、記法の違いが分からなかった。

### FR-010 数式の描画

- 本文の数式の書き方:
  - インライン: `$…$` で囲む。開きの `$` の直後と閉じの `$` の直前が空白でなく、閉じの `$` の直後が数字でない場合に数式とする（「$5 と $10」のような金額を数式にしないため）。
  - ブロック: `$$` だけの行で囲む。段落の中の `$$…$$` も、独立した行の数式（ディスプレイ数式）として描画する。
  - `\$` と書くと `$` を文字として表示する。コード（インラインコード・コードブロック）の中の `$` は数式にしない。
- 図の中の数式: Mermaid のフローチャートとシーケンス図のラベルに `$$…$$` で書く。Mermaid（`10.9.1`）の数式機能で描画するため、対象の図種は Mermaid が数式に対応している図種に限る。
- 数式の書き方に誤りがある場合は、その数式だけを誤りと分かる表示にし、他の内容の描画は続ける。
- 数式ライブラリを読み込めない場合（オフラインなど）は、数式を書いたとおりの文字で表示する。
- `sample.md` には、インライン数式、ブロック数式（複数行の数式・行列を含む）、数式にならない `$` の例、フローチャートとシーケンス図の中の数式の例を記載する。
- 背景: 技術文書では数式を使うことが多い。本文の数式の書き方は、GitHub など多くの Markdown 環境と同じ `$` / `$$` の記法に合わせる。

## 4. 非機能要求 (NFR)

| ID      | 項目                   | 内容                                                                        |
| :------ | :--------------------- | :-------------------------------------------------------------------------- |
| NFR-001 | スタンドアロン動作     | バックエンド API を必要とせず、ブラウザのみで完結して動作する               |
| NFR-002 | キャッシュとエラー耐性 | FNV-1a ハッシュによる SVG キャッシュで再描画を高速化し、構文エラー時は直前の正常描画（LKG）を保持する |
| NFR-003 | セキュリティ           | Markdown から生成した HTML は DOMPurify でサニタイズしてから DOM に反映する |
| NFR-004 | 図の視認性             | シーケンス図のライフライン（縦の線と活性区間の矩形）と矢じりは、通常モード・Visual Stage の 4 スタイル・Light / Dark のどの組み合わせでも背景と見分けられる線の色・枠線・塗りの色で描画する |
| NFR-005 | 大きな図の判読性       | 図を表示枠の幅に合わせる表示（`Fit`）でも、図の中の文字を表示上 10px 以上の大きさに保つ（Mermaid が生成した文字がもともと 10px 未満の場合は、元の大きさ以上に保つ）。表示枠に収まらない部分は横スクロールで表示する。図の中の数式は、線や他の文字と重ならない |
