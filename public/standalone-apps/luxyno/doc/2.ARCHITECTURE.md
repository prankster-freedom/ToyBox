# アーキテクチャ設計書 (2.ARCHITECTURE.md)

## 1. はじめに

本書は `public/standalone-apps/luxyno/` で管理する **Luxyno — Exhibition-Grade Markdown Viewer** のアーキテクチャ設計を記述する。今後の増分開発（`swe2-1`）に伴い更新する。

設計の判断は、要求仕様書の [1.1 プロダクトコンセプト](1.SPEC.md#11-プロダクトコンセプト) に従う。

- **通常モード**: 軽快さを最優先する（`NFR-006`）。起動時に読み込むものや、入力のたびに行う処理を増やすときは、その費用を評価し、必要になるまで遅らせる・結果を使い回すなどの方法を先に検討する。
- **Visual Stage**: 見た目の品質を優先する（`NFR-007`）。Visual Stage への切り替え時の描画や、Publishing の操作（画像・HTML の書き出しを含む、発表用に整える操作全般）の処理が重くなるのは許容する。ただし、スクロール・表示倍率の切替・拡大表示などの閲覧の操作は、即座に反応させる。

## 2. 制約と利用技術

- **動作環境**: モダン Web ブラウザ（クライアントサイド完結、`NFR-001`）
- **構成**: Vanilla HTML / CSS / JavaScript（ビルドステップなしでもそのまま配信・実行可能）
- **外部ライブラリ（CDN）**:
  - Tailwind CSS（UI スタイリング補助）
  - Marked `12.0.2`（Markdown トークナイズ・パース）
  - DOMPurify `3.1.6`（HTML サニタイズ、`NFR-003`）
  - Mermaid `10.9.1`（ダイアグラム SVG 生成。図の中の数式は Mermaid に同梱の数式機能で MathML として描画する）
  - KaTeX `0.16.9`（本文の TeX 数式の描画、`FR-010`。JavaScript と CSS）

## 4. 主要な設計判断

### 4.1 ファイルの読み込み方法（`FR-006`, `FR-007`）

- ブラウザのファイル選択（`<input type="file">` と `FileReader`）で読み込む。`index.html` を `file://` で直接開いた場合も動作させるため（`NFR-001`）。
- 採らなかった案: 起動時に `fetch('./sample.md')` で自動読み込みする案。`file://` ではブラウザの制約で読み込めず、開き方によって動作が変わるため。
- 詳細は [file-loading.md](3.detailed_design/features/file-loading.md) を参照する。

### 4.2 図の描画先と SVG 内の id（`FR-003`, `FR-008`, `NFR-004`）

- 表示していない側のプレビュー（通常モード / Visual Stage）は、描画のたびに空にする。両方に図を残すと、`data-stage-index` と SVG 内の id が DOM 上で重複し、描画結果の書き込み先や、矢じり・グラデーションの参照先が非表示側に向くため。
- Mermaid はシーケンス図の矢じり（`#arrowhead` など）や ER 図の端点を、図をまたいで同じ id で出力する。SVG の後処理で、SVG 内の id を SVG ごとに一意な名前に置き換える。
- 詳細は [diagram-rendering.md](3.detailed_design/features/diagram-rendering.md) を参照する。

### 4.3 図種ごとの装飾の範囲（`FR-008`）

- Visual Stage のノード装飾（形・塗りの置き換え）は、flowchart・状態遷移図・シーケンス図に限る。その他の図種は、Mermaid の配色変数にスタイルごとの配色を渡して描画し、SVG の構造には手を加えない。
- 背景: ノード装飾は `g.node` などの要素を前提にしており、クラス図など他の図種の同名要素に適用すると、図の構造が崩れるため。
- Visual Stage のカード背景は、Light / Dark によらず明るい色である。このため、Visual Stage の図は外観によらず明るい配色で描画する。Dark でもカードが明るいことは既知の課題として [Issue #13](https://github.com/prankster-freedom/ToyBox/issues/13) で管理している。

### 4.4 Markdown 要素の表示（`FR-009`）

- Tailwind CSS（CDN）の Preflight と `style.css` の全要素リセット（`* { margin: 0; padding: 0; }`）により、ブラウザ標準の要素のスタイルは初期化される。Markdown から生成する要素（見出し、リスト、リンク、コード、引用、表、水平線、標準の HTML 要素）の表示は、すべて `style.css` で定義する。
- 通常モード（`.prose-doc`）と Visual Stage の本文（`.exhibition-slab`）は、同じ要素スタイルを共有し、色は Light / Dark のデザイントークン（CSS 変数）から取る。Visual Stage の本文の背景（スラブ）は、図のカードと異なり、外観に合わせて Light / Dark で切り替わるため。
- 採らなかった案: Tailwind の Typography プラグイン（`prose` クラス）を使う案。プラグインは独自の文字サイズ・余白・配色を持つため、既存の `.prose-doc` の組版（`h1`・`h2`・表）と重複する。また、Light / Dark のトークンやパレット（`--accent`）と連動させるには、結局すべての色を上書きする必要があるため。
- 詳細は [markdown-typography.md](3.detailed_design/features/markdown-typography.md) を参照する。

### 4.5 数式の描画（`FR-010`, `NFR-003`）

- 本文の数式は、Marked の拡張で `$…$` / `$$…$$` を数式の置き場所（TeX の原文を属性に持つ `span` / `div`）に置き換える。DOMPurify でサニタイズした後に、置き場所へ KaTeX で描画する。
- 背景: KaTeX の出力（MathML と、`style` 属性を多用する HTML）をサニタイズにかけると、必要な要素・属性が削られて崩れる。サニタイズ後に KaTeX が自身で安全に生成した要素を入れることで、`NFR-003` を保ったまま正しく表示する。KaTeX は信頼できない入力を前提とした設定（`trust: false`、既定）で使う。
- 置き場所の中身は TeX の原文とし、KaTeX を読み込めない場合は原文がそのまま表示される。
- 図の中の数式は、Mermaid 自身の数式機能に任せる。Mermaid は数式を MathML として出力するため、KaTeX の CSS に依存しない。
- 採らなかった案: 数式を Mermaid と同じく非同期の描画キューで処理する案。KaTeX の描画は同期で十分に速く、キャッシュの仕組みを増やす必要がないため。
- HTML エクスポートはページ全体を書き出すため、`<head>` の KaTeX の CSS の読み込みも含まれる。

### 4.6 図の表示倍率（`NFR-005`）

- `Fit` は図を表示枠の幅に合わせるが、図の中の最も小さい文字が表示上 10px 未満になる縮小はしない。縮小の下限は、図を描画した後に図の中の文字の大きさを調べて、図ごとに決める。
- 背景: ノードの多い図や横長の図（ガント、ジャーニー、タイムラインなど）は、幅に合わせると文字が 7px 前後まで縮み、判読できなかった。
- 採らなかった案: 縮小率の下限を固定値にする案。図種によって Mermaid が使う文字の大きさが異なり（10〜16px）、固定値では判読できない図と、不要に横スクロールになる図が出るため。
