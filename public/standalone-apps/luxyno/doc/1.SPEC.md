# 要求仕様書 (1.SPEC.md)

## 1. 概要

**Luxyno — Exhibition-Grade Markdown Viewer** は、Markdown 文書と Mermaid ダイアグラムを表示・エクスポートするスタンドアロンの Web アプリケーション（Markdown ビューアー）である。
エンジニアリング仕様書向けのクリーンな通常表示モードと、インフォグラフィック調の 4 スタイルを切り替えられる「Visual Stage」モードを備える。

- 製品の位置づけは Markdown ビューアーである。エディタ（左ペインでの編集とリアルタイムのプレビュー）は、当面は付随的な機能とし、要求の優先度はビューアーとしての表示・閲覧の機能より低い。
- 旧名称は Linea である。過去のコミット・Pull Request（#11, #12 など）では旧名称を使っている。

初期プロトタイプの機能・デザイン仕様は [luxyno_functional_and_design_specification.md](luxyno_functional_and_design_specification.md) を参照する。

### 1.1 プロダクトコンセプト

要求の追加・変更や設計の判断は、本節のコンセプトに照らして行う。

**差別化のポイント**

- 既存の Markdown / Mermaid ビューアーより洗練されたデザインで、Mermaid の図を描けること
- 軽快に動作すること

**2 つのモードの位置づけ**

| モード       | 最優先すること                               | 目指す水準 |
| :----------- | :------------------------------------------- | :--------- |
| 通常モード   | 軽快に動作すること（至上命題）               | 起動から、その後の編集・閲覧の操作まで、すべての場面で待たされない |
| Visual Stage | 見た目の品質。閲覧操作のリアルタイム性は保つ | 各種イベントやショーの講演資料・展示素材として、そのまま表示できる。簡易ビューアーで描画していると感じさせない、プロのデザイナーが制作したと思える品質。全体の構図から細部の質感までこだわる |

**判断の指針**

- 通常モードで、速度と見た目・機能が衝突するときは、速度を優先する。起動時の読み込みや、入力のたびに行う処理を増やす変更は、その費用を評価してから採る。
- Visual Stage で、品質と速度が衝突するときは、品質を優先する。品質のために、起動（Visual Stage への切り替え、スタイルの切り替えによる描画）や Publishing の操作（画像・HTML の書き出しを含む、発表用に整える操作全般）が重くなるのは許容する。ただし、閲覧の操作（スクロール、図の表示倍率の切替、拡大表示など）は、講演・展示の進行に支障が出ない程度のリアルタイム性を保つ。

### 1.2 ブランドコンセプト（Luxyno — Brand Concept Sheet）

**Luxyno — Exhibition-Grade Markdown Viewer**（読み：ルキシノ）

本節は、1.1 のプロダクトコンセプトを表現するブランドの定義である。製品名・ロゴ・配色などの表現は本節に従う。

- 製品名は、画面の表示・`<title>`・フォルダ名（`public/standalone-apps/luxyno/`）・ドキュメント・コード上の名前（クラス名など）のすべてで Luxyno を使う。
- 1.2.5 のビジュアル展開（ロゴ、シンボルマーク、ブランドカラー）の画面への反映は未対応。
- ブランドカラー（ダーク基調）は、ブランドの表現（ロゴ、アプリの外枠など）に使う。Visual Stage の図・カードの配色をブランドカラーに合わせる必要はない（Visual Stage の配色は、4 スタイルそれぞれのデザインに従う）。

#### 1.2.1 ネーミングの構造と音韻設計（Phonetics & Origin）

- **語源の核**: `Lux`（ラテン語：光・輝き・照度） ＋ `-yno`（端正な佇まい・完結性を生む現代的サフィックス）
- **音の構成**:
  - 立ち上がりの **「Lu-」**：滑らかで淀みのない母音の抜け。思考を妨げない軽快性とノーストレスな書き味を表現。
  - 中央の鋭利な **「-x-」**：エンジニアリングの厳密さ、Mermaid記法が持つ構造化のシャープなエッジ。
  - 結びの **「-yno」**：イタリア語・ラテン語調の落ち着いた調和。ツールとしての安定感と、展示・カンファレンスにふさわしい洗練された品格。
- **アイデンティティ**: 既存の英単語や陳腐化したテック接尾辞に依存しない完全な造語であり、Webおよびグローバルソフトウェア領域において濁りのないクリーンな認知を確立。

#### 1.2.2 コア・フィロソフィー（Philosophy）

> **「構文に、光と舞台を。」**
> 単なるプレーンテキストの変換器ではなく、エンジニアが紡ぐロジックの構造美を、そのままスポットライトの当たるステージへと引き上げる。

開発者が日常的に求める「極めて軽快な動作」を基盤に敷きながら、ひとたびモードを切り替えれば、そのまま各種イベント、基調講演、展示ブースの大画面で主役を張れるクオリティを創出する。

「簡易ビューアーで出力した図」という妥協を完全に過去のものにし、プロのデザイナーが緻密に設計したかのような構図・質感・ライティングを提供する。

#### 1.2.3 デュアルモードの体験設計

- **Normal Mode ── 思考を邪魔しない絶対的軽快性**: 一切のラグや無駄な装飾を排し、ミリ秒単位でレスポンスする高速レンダリング環境。MarkdownとMermaidを素早く打ち込み、思考のスピードでアイデアを具現化する。（`NFR-006`）
- **Visual Stage Mode ── 展示素材として完成されたプロ品質**: ノードの配置バランス、タイポグラフィのカーニング、微細なシャドウ、線と光の陰影処理までを極限までチューニング。「Lux（光）」の名が示す通り、大画面で映える立体感と洗練されたトーン＆マナーで、発表者とプロダクトの信頼性を最大限に引き上げる。（`NFR-007`）

#### 1.2.4 タグラインが約束する提供価値

**— Exhibition-Grade Markdown Viewer —**

- **Exhibition-Grade（展示会・展示素材品質）**: 「Presentation」や「Slide」といった日常的な枠組みを超え、モーターショー、テックカンファレンス、デザインエキシビションなどの**最高峰の舞台にそのまま掲出できる基準**を満たしていることを端的に宣言。
- **Markdown Viewer**: ベースが極めて直感的かつオープンなMarkdown / Mermaid記法であることを明示し、開発者やテクニカルライターが学習コストゼロで導入できる道具としての誠実さを担保。

#### 1.2.5 ビジュアル展開の指針（Visual Tone & Style）

- **ロゴ表記**: `LUXYNO`（オールキャップスで硬質な信頼感）または `Luxyno`（幾何学的サンセリフによるミニマルモダン）
- **シンボルマーク**: 「L」と「X」の交差、あるいは光のプリズム・ノードの結節点をモチーフにした、ソリッドで抽象度の高いアイコン
- **ブランドカラー**: 深みのあるダークスレート／オブシディアンブラックを基調に、冷涼で純度の高いアクセントライト（ペールシアン、ルミナスホワイト）

### FR-006 Markdown ファイルの読み込み

- エディタの内容を、最後に読み込んだ時点から編集していた場合（起動直後の空の状態から入力した場合を含む）は、置き換える前に確認ダイアログを表示し、取り消せるようにする。本アプリには保存機能がなく、置き換えると編集内容が失われるため。
- ブラウザのファイル選択で読み込むため、`index.html` を `file://` で直接開いた場合でも使える。

### FR-007 起動時の初期表示

- サンプル文書は `app.js` に埋め込まない。サンプルは同梱の `sample.md` として提供し、利用者が FR-006 で開く。
- 背景: 埋め込みの文書はソースコードの中にあり、内容の確認・更新がしにくい。起動時に `sample.md` を自動で読み込む案は、`file://` で開いた場合にブラウザの制約で読み込めず、開き方によって動作が変わるため採らない。

### FR-008 同梱サンプルの全図種の描画

- `sample.md` には、Markdown の主な記法と、Mermaid（`10.9.1`）で描ける主な図種の簡単な例を記載する。
- 「意図どおり」とは、次をすべて満たすことをいう。
  - 構文エラーにならず、Mermaid が生成した図の構造（要素の形・配置・接続）が崩れない
  - 文字・線・矢じり・塗りが背景と見分けられ、判読できる（`NFR-004`）
  - Visual Stage の各スタイルの装飾（グラデーション、カード化、円形化など）は、その図種で意味の通る要素にだけ適用する。適用できない図種は、構造を保ったまま、そのスタイルの配色・背景に合わせる
- 背景: Visual Stage の装飾は flowchart・状態遷移図・シーケンス図を前提に作られており、他の図種の要素にそのまま適用すると図が崩れるため。
- `sample.md` には、図種ごとの簡単な例に加え、ノードの多いフローチャート（サブグラフを含む）と、状態の多い状態遷移図（複合状態・分岐・並行を含む）を記載し、大きな図の判読性（`NFR-005`）を確認できるようにする。

### FR-009 同梱サンプルの Markdown 記法の描画

- 「記法ごとに見分けられる」とは、Light / Dark のどちらでも、次をすべて満たすことをいう。
  - 見出しは階層ごとに文字の大きさまたは太さが異なり、本文と見分けられる
  - 箇条書きには記号、番号付きリストには番号が付き、入れ子は字下げされる
  - リンクは本文と異なる色で、リンクと分かる
  - インラインコードとコードブロックは、本文と異なる背景と等幅フォントで表示される
  - 引用は、本文と見分けられる左線と字下げで表示される
  - 表の列は、Markdown で指定した寄せ（左・中央・右）で表示される
  - 水平線は、背景と見分けられる線で表示される
  - HTML で書いた標準の要素（`details` / `summary`、`kbd`、`mark`、`sub` / `sup` など）は、その要素と分かる表示になる
- `sample.md` の HTML の例には、アプリ独自の class を使わず、標準の HTML 要素だけを使う。アプリ独自の装飾（`callout-box`）を使うと、標準の HTML の表示例と区別できないため。
- 背景: 本アプリが読み込む Tailwind CSS は、ブラウザ標準の要素のスタイル（見出しの大きさ、リストの記号、リンクの色など）を初期化する。アプリ側で定義していない要素は本文と同じ表示になり、記法の違いが分からなかった。

### FR-010 数式の描画

- 本文の数式の書き方:
  - インライン: `$…$` で囲む。開きの `$` の直後と閉じの `$` の直前が空白でなく、閉じの `$` の直後が数字でない場合に数式とする（「$5 と $10」のような金額を数式にしないため）。
  - ブロック: `$$` だけの行で囲む。段落の中の `$$…$$` も、独立した行の数式（ディスプレイ数式）として描画する。
  - `\$` と書くと `$` を文字として表示する。コード（インラインコード・コードブロック）の中の `$` は数式にしない。
- 図の中の数式: Mermaid のフローチャートとシーケンス図のラベルに `$$…$$` で書く。Mermaid（`10.9.1`）の数式機能で描画するため、対象の図種は Mermaid が数式に対応している図種に限る。
- 数式の書き方に誤りがある場合は、その数式だけを誤りと分かる表示にし、他の内容の描画は続ける。
- 数式ライブラリを読み込めない場合（オフラインなど）は、数式を書いたとおりの文字で表示する。
- `sample.md` には、インライン数式、ブロック数式（複数行の数式・行列を含む）、数式にならない `$` の例、フローチャートとシーケンス図の中の数式の例を記載する。
- 背景: 技術文書では数式を使うことが多い。本文の数式の書き方は、GitHub など多くの Markdown 環境と同じ `$` / `$$` の記法に合わせる。

## 4. 非機能要求 (NFR)

| ID      | 項目                    | 内容                                                                        |
| :------ | :---------------------- | :-------------------------------------------------------------------------- |
| NFR-001 | スタンドアロン動作      | バックエンド API を必要とせず、ブラウザのみで完結して動作する               |
| NFR-002 | キャッシュとエラー耐性  | FNV-1a ハッシュによる SVG キャッシュで再描画を高速化し、構文エラー時は直前の正常描画（LKG）を保持する |
| NFR-003 | セキュリティ            | Markdown から生成した HTML は DOMPurify でサニタイズしてから DOM に反映する |
| NFR-004 | 図の視認性              | シーケンス図のライフライン（縦の線と活性区間の矩形）と矢じりは、通常モード・Visual Stage の 4 スタイル・Light / Dark のどの組み合わせでも背景と見分けられる線の色・枠線・塗りの色で描画する |
| NFR-005 | 大きな図の判読性        | 図を表示枠の幅に合わせる表示（`Fit`）でも、図の中の文字を表示上 10px 以上の大きさに保つ（Mermaid が生成した文字がもともと 10px 未満の場合は、元の大きさ以上に保つ）。表示枠に収まらない部分は横スクロールで表示する。図の中の数式は、線や他の文字と重ならない |
| NFR-006 | 通常モードの軽快さ      | 起動から、Markdown の入力、プレビューの閲覧、モードや表示の切替まで、通常モードのすべての操作で利用者を待たせない（コンセプト 1.1）。具体的な基準（応答時間、想定する文書の規模、計測の方法）は未確定 |
| NFR-007 | Visual Stage の表示品質 | 講演資料・展示素材としてそのまま表示できる品質で描画する。閲覧の操作は進行に支障が出ない程度に即座に反応する（コンセプト 1.1）。品質の判定の基準（評価の観点、判定する人）は未確定で、当面は目視確認（`TC-DIAG-005` など）で判断する |
