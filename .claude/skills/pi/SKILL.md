# pi（プロセス改善）

直近の会話や不具合を振り返ってプロセス改善を行う。

振り返りの対象・観点: $ARGUMENTS

## 手順

1. **振り返り**: 直近の会話の内容や不具合を振り返り、`AGENTS.md`、`.claude/skills/` 配下のスキル、`agents-support-tools/` 配下の補助スクリプトの問題点を洗い出す。ドキュメント構成や命名規則なども、最新のプロジェクト状況を踏まえて見直す。
2. **【承認】改定案の提示**: 問題点と改定案をユーザーとレビューし、承認を得る。改定案には、対象ファイル・変更内容の差分（変更前と変更後）・変更の理由（具体的な失敗経験や指摘など）・コミットの型（版の上げ方）を示す。
3. **改定の反映**: 承認された改定案をドキュメントへ反映する。合意に至った経緯や根拠は、コミットメッセージの本文に残す。`.cursor/` などの他の AI ツール向けフォルダへの反映は不要（`AGENTS.md` 3 章）。
4. **【承認】最終版の確認**: 反映後の最終版をユーザーに報告し、明示的に承認を得たら完了とする。

## 改定時の注意

- `AGENTS.md` には全作業に共通する原則だけを書く。特定のスキルにだけ関係するルールはそのスキルに書き、`AGENTS.md` の肥大化を防ぐ。`CLAUDE.md` には原則を書かない。
- 承認が必要な工程には【承認】を付ける（書き方は `.claude/README.md` の「承認工程の書き方」）。
