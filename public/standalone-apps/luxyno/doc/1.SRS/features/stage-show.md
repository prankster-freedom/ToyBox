# Feature Requirement Specification: stage-show

本ドキュメントは、Luxyno の Visualモードの舞台演出の要求を定める。図の構造に沿って光を伝える表現（`FR-018`）と、講演・展示の大画面で文書をそのまま見せる表示（`FR-019`）、発表中の俯瞰（`FR-022`）と光のポインター（`FR-023`）からなる。

対応する全体 SRS: [doc/1.SRS.md](../../1.SRS.md)／デザイン仕様: [0.DTP/features/stage-show.md](../../0.DTP/features/stage-show.md)

## 対象機能要求一覧

| ID     | 機能名                         | 概要                                                                 |
| :----- | :----------------------------- | :------------------------------------------------------------------- |
| FR-018 | Visualモードのシグナル・ライト | 図の結線と手順の接続線の上を、図の構造に沿って光が伝わり、届いたノードや手順の丸が反応する |
| FR-019 | Visualモードのステージ発表     | 章を 1 シーンとして全画面でページ送りし、1 項目ずつの表示と自動進行で講演・展示に使える |
| FR-022 | 発表の俯瞰（ライトテーブル）   | 発表中に全シーンを実物のまま縮小して並べ、選んだシーンへ拡大して入る |
| FR-023 | 発表の光のポインター           | 発表中にマウスの位置へスポットライトを当て、指している場所を示す     |

---

## 機能要求の詳細

### FR-018: Visualモードのシグナル・ライト

- フローチャート・状態遷移図では、光が入る線のないノードから出発し、結線をたどって下流へ伝わること。ノードに最初に光が届いた時刻に、そのノードから出る結線の光が出発すること（`DTP-LIGHT-040`）。
- シーケンス図では、メッセージの光が時系列の順に 1 本ずつ流れること。
- 光は、白に近い芯と色の付いた光輪を持ち、尾に向かって細く薄くなること（`DTP-LIGHT-010`）。Light / Dark のどちらの背景でも光として見えること（`DTP-LIGHT-020`）。
- 光が届いたノードは、輪郭の外側が光る形で反応すること。ノードの文字の読みやすさを損なわないこと（`DTP-LIGHT-030`）。
- 手順型の接続線の上を光が進み、届いた丸が反応すること（`DTP-LIGHT-050`）。
- 表示の倍率（`Fit` / `1:1`）、ビューモード（`Split` / `Canvas`）、拡大モーダル、ステージ発表のどれでも、光が線の上から外れないこと。
- PNG / SVG の書き出しに光が含まれないこと。
- **閲覧のリアルタイム性（`NFR-007`）**:
  - 画面の外の図では光を動かさず、図が画面に入るまでは光の計算もしないこと。
  - 図が表示されている間も、スクロールなどの閲覧の操作が滑らかに動くこと。
- **高速モードへの影響（`NFR-006`）**: 高速モードでは光を出さず、光の処理の読み込みもしないこと。
- **動きを減らす設定**: `prefers-reduced-motion: reduce` では光を出さないこと。
- **背景・根拠**:
  - 以前の演出は、線の上を短い破線が動くだけで、光として読めず、図の意味も伝えなかった（[デザイン仕様の根拠](../../0.DTP/features/stage-show.md#光の表現の見直しの根拠)）。光を「図の意味を運ぶ信号」にすることで、発表者の説明の順序と聴衆の視線を揃える。
  - 以前の演出は SVG の中に線を足していたため、CSS のない PNG / SVG の書き出しで、線が黒い塗りのくさび形になった。光を SVG の外に描くことで、書き出しへの混入を構造的に防ぐ。
- **採らなかった案**: SVG のフィルターでぼかす案（`RGH-904`）、波紋の輪（`RGH-905`）。

### FR-019: Visualモードのステージ発表

- ヘッダーの「発表」ボタンで、現在の文書を全画面で発表できること。高速モードからも 1 回の操作で始められること。
- 1 シーンに 1 章（`h2`）を表示し、表紙（ヒーロー）のシーンから順に送れること。アプリの操作部品は表示しないこと（`DTP-SHOW-020`）。
- 発表は Dark の舞台で始まり、`T` キーで Light に切り替えられること（`DTP-SHOW-010`）。切り替えても表示中のシーンを保つこと。
- 操作: 次へ（`→` / `↓` / `Space` / `Enter` / `PageDown` / クリック）、前へ（`←` / `↑` / `Backspace` / `PageUp`）、先頭・末尾（`Home` / `End`）、自動進行（`A`）、明暗（`T`）、俯瞰（`O`。`FR-022`）、光のポインター（`L`。`FR-023`）、終了（`Esc`）。操作ボタンにも、一覧・ポインターを置く。
- 要点カード・手順は 1 項目ずつ表示すること。すべて表示してから次のシーンへ進むこと（`DTP-SHOW-050`）。
- 画面に収まらない章は、次のシーンへ進む前に残りをスクロールで見せること。
- 図は舞台の残りの高さに収めること。ただし文字の下限（`NFR-005`）を保つこと（`DTP-SHOW-030`）。
- 自動進行では、項目を 2.4 秒ごと、シーンを 7 秒ごとに送り、図のあるシーンでは光が一巡してから送ること。最後のシーンの次は先頭へ戻ること（無人の展示向け）。
- 終了すると、発表前の外観・ビューモードに戻り、最後に見せていた章を通常の表示で見える位置に出すこと。
- 章のない文書（本文が空）では発表を始めず、その旨を通知すること。
- **閲覧のリアルタイム性（`NFR-007`）**: ページ送りは即座に反応すること。シーンの切り替えで図を再描画しないこと。
- **背景・根拠**:
  - コンセプト（[1.1](../../1.SRS.md#11-プロダクトコンセプト)）は「各種イベントやショーの講演資料・展示素材として、そのまま表示できる」ことを求めるが、操作部品が見えたままではビューアーらしさが残り、この水準に届かなかった（Issue #20）。
  - 既存の Markdown に手を加えずに発表できることが差別化になる。そのため、シーンの区切りは新しい記法を設けず、章（`h2`）とする（`RGH-901`）。
  - スライドの作り直しが不要になることが、発表の準備の手間を大きく減らす。
- **採らなかった案**: 発表者用の手元画面（`RGH-106`、ストック）。

### FR-022: 発表の俯瞰（ライトテーブル）

- 発表中に `O` キーまたは操作ボタンの「一覧」で、全シーン（表紙を含む）を縮小して格子に並べた俯瞰を開けること。デザインはデザイン仕様（`DTP-SHOW-070`）に従う。
- 縮小図は、発表で表示するシーンと同じ構図・内容であること。
- 開いた直後は、話していたシーンを選んでいること。選んでいるシーンと、その章の題・位置（`06 / 15`）が分かること。
- 矢印キー（上下は 1 行分）、`Home` / `End` で選択を動かし、`Enter` / `Space` / クリックで選んだシーンへ入れること。別のシーンへ入ったときは、要点カード・手順をすべて表示した状態で出すこと。
- `O` / `Esc` で、開く前のシーンへ、開く前の表示の状態のまま戻れること。発表は終わらないこと。
- 俯瞰の間は、図の光を止めること。シーンへ入ったら、そのシーンの光が流れること。
- 俯瞰の間に明暗（`T`）を切り替えても、俯瞰と選択を保つこと。
- 自動進行中に開いたら自動進行を止め、光のポインターも消すこと。
- **閲覧のリアルタイム性（`NFR-007`）**: 開く操作から縮小図が並ぶまでを 0.4 秒未満とすること。縮小図のために図を再描画・複製しないこと。
- **背景・根拠**:
  - 初期ユーザーは、発表のかっこよさと、それにもかかわらず軽快に動くことを最も高く評価した。発表の価値をさらに高める機能を、同じ軽さで足す。
  - これまでの発表は 1 シーンずつしか見えず、全体の構成・現在地を示す手段も、質疑で特定の章へ戻る手段もなかった（`→` / `←` の連打か `Home` / `End` だけ）。スライドツールのライトテーブルにあたる俯瞰で、構成を見せ、章を選んで戻れるようにする。
  - Markdown の章からそのまま俯瞰が作られることは、スライドを作り直さない Luxyno ならではの体験である。
- **採らなかった案**: 縮小図を画像にして並べる案（`RGH-109`）。開くまで待たせ、発表の表示と見た目がずれる。

### FR-023: 発表の光のポインター

- 発表中に `L` キーまたは操作ボタンの「ポインター」で、光のポインターの表示を切り替えられること。デザインはデザイン仕様（`DTP-SHOW-080`）に従う。
- 光のポインターは、マウスの位置に光の粒を置き、その周りを明るく、それ以外の舞台を沈めること。光の外の文字も読めること。
- 表示中はマウスのカーソルを隠すこと。クリックによる送り（`FR-019`）は変えないこと。
- 俯瞰を開いたとき、発表を終えたときは消すこと。
- **閲覧のリアルタイム性（`NFR-007`）**: マウスの動きに遅れずに追従し、追従の処理で要素の大きさ・位置を読まないこと（レイアウトの計算を起こさない）。
- **背景・根拠**: 大画面の発表では、発表者が「ここ」を指す手段がなかった（発表中はマウスのカーソルが消える）。レーザーポインターを別に用意しなくても、舞台照明のスポットライトとして指せるようにする。色は Luxyno のブランドのアクセントライトとし、文書の配色と区別する（`DTP-003`）。
- **採らなかった案**: 周りを強く沈める案（`RGH-908`）。光の外の文字が読めなくなった。
