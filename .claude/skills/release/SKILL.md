# release（リリース）

ユーザーからリリースの指示があった場合にのみ、この手順を実行する。版の決め方は `AGENTS.md` 1.9 に従う。

対象の単位: $ARGUMENTS

## 手順

1. **対象と前回のリリースの確認**: 対象の単位について、版番号を置いたファイル（下記「単位ごとの置き場所」）と、前回のリリースのコミット（版番号を最後に変更したコミット）を確認する。

   ```sh
   git log -1 --format='%h %s' -G '^ *version:' -- <版番号を置いたファイル>
   ```

2. **コミットの収集**: 前回のリリース以降に、その単位のファイルを変更したコミットを集める。

   ```sh
   git log --format='%h %s' <前回のリリースのコミット>..HEAD -- <単位のパス>
   ```

   - スコープが単位名と一致しないコミットや、Conventional Commits の形式に沿わないコミットがあれば、一覧にしてユーザーに報告する
   - 版を上げるコミット（下記）が 1 つもない場合は、リリースせずにその旨を報告する
   - `doc` のコミット（Markdown の変更）は版を上げない。ドキュメント（スキルや文書）自体は、ユーザーがリリースの対象に指定した場合だけリリースする
3. **版の決定**: 集めたコミットのうち最も大きい変更で版を決める。`!` または `BREAKING CHANGE:` があれば MAJOR、`feat` があれば MINOR、`fix` だけなら PATCH を上げる。ユーザーがドキュメント自体をリリースの対象に指定した場合は、`doc!` を MAJOR とし、それ以外の `doc` は説明から追加（MINOR）か修正（PATCH）かを判断して、手順 4 で確認を受ける。MAJOR を上げたら MINOR と PATCH を 0 に、MINOR を上げたら PATCH を 0 に戻す。
4. **【承認】版とリリースノート案の確認**: 単位ごとに、現在の版・新しい版・リリースノート案（下記の形式）を示し、承認を得る。
5. **反映**: 承認された内容で、版番号を更新し、単位の `README.md` のリリースノートに新しい版の節を追加する。`README.md` の一覧に版番号を載せている場合は、その値も更新する。
6. **リリースコミット**: 単位ごとに `chore(release): <単位名> v<新しい版>` でコミットし、コミット ID を報告する。push は、ユーザーから指示があるときのみ行う。
7. **タグ**: リリースコミットを main へマージした後（commit スキルのブランチ規則に従い Rebase and merge）、main 上のリリースコミットに注釈付きタグ `<単位名>-v<新しい版>`（例: `sample-app-v1.2.0`）を付ける。タグの push は、ユーザーから指示があるときのみ行う。

## リリースノートの形式

新しい版を節の先頭に追加する。各行は、コミットのタイトルを型ごとに並べる（`!` 付き、`feat`、`fix` の順）。版を上げない型のコミットは載せない。

```markdown
### 1.2.0（yyyy-mm-dd）

- feat!: <タイトル>
- feat: <タイトル>
- fix: <タイトル>
```

## 単位ごとの置き場所

| README の持ち方                                                            | 版番号 | リリースノート |
| :------------------------------------------------------------------------- | :----- | :------------- |
| 単位ごとに `README.md` を持つ（例: ソフトウェアのプロジェクト）            | 単位の `README.md` の Front Matter の `version` | 単位の `README.md` の「リリースノート」 |
| 1 つの `README.md` で複数の単位をまとめる（例: スキル、`doc/` 直下の文書） | 各単位の本体ファイル。スキルは `SKILL.md` の `metadata.version`、文書はその文書の Front Matter の `version` | まとめた `README.md`（`.claude/README.md`、`doc/README.md`）の「リリースノート」に、単位ごとの節を設けて記載 |
